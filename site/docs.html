Getting Started

Fogoe Documentation

Fogoe is a high-performance backend scaffolding engine for Node.js and TypeScript. It generates clean, production-grade backends in seconds across Express, Fastify, Hono, and Koa without runtime bloat or restrictive abstractions.

Pure Disk-Based Template Architecture
Fogoe does not embed massive template strings into generator source files. Every template is maintained as real, valid on-disk code files, preventing escaping bugs and guaranteeing syntax accuracy.

Core Engineering Philosophy #

  • Zero Friction: Go from an idea to a fully wired, compiling, and running HTTP API in under 30 seconds.
  • Zero Lock-in: You own 100% of the generated codebase. No custom runtime wrappers, meta-framework dependencies, or proprietary CLIs are required in production.
  • Modern Standards: Built natively around strict TypeScript 5.x, NodeNext module resolution, ES Modules ("type": "module"), and industry-standard ORMs like Drizzle and Prisma.
  • Agent & CI Native: Built from the ground up to support autonomous coding agents (Claude Code, Cursor, Copilot, Antigravity) with non-interactive flags and machine-readable --json output.

Installation & Execution #

Fogoe requires Node.js >= 18.0.0. You can run Fogoe on-demand using any major package manager without global installation:

bash
$ npx fogoe

$ npm install -g fogoe $ fogoe --version

Quick Start Guide #

Fogoe offers two primary workflows: interactive terminal wizard for humans, and headless CLI flags for automation and coding agents.

1. Interactive Terminal Wizard (Clack TUI)

Running npx fogoe create <name> launches an interactive step-by-step wizard powered by @clack/prompts:

Terminal Wizard Flow
$ npx fogoe create payment-api ◇ Welcome to Fogoe v1.1.1 │ ◇ Select web framework › Fastify (High-performance API) ◇ Select language › TypeScript (Strict NodeNext ESM) ◇ Architecture pattern › MVC (Layered routes/controllers/models) ◇ Database / ORM › Drizzle ORM (PostgreSQL) ◇ Authentication › JWT Bearer (authMiddleware) ◇ Initialize Git repo? › Yes (with stack-tailored .gitignore) ◇ Install dependencies?› Yes (using detected npm/pnpm) │ └ ✔ Project scaffolded successfully in 38ms!

2. Single-Command Headless Flag Mode

Pass explicit flags to bypass interactive prompts entirely—ideal for CI/CD pipelines, Dockerfiles, and custom scripts:

bash
$ fogoe create store-api \ --framework fastify \ --lang ts \ --db drizzle \ --auth jwt \ --git \ --install \ -y

CLI Commands Reference

Fogoe includes a complete toolchain for project initialization, component generation, plugin configuration, and Git repository synchronization.

Command Arguments / Flags Description
fogoe [name] Optional target directory name Launches the interactive TUI wizard to initialize a project.
fogoe create <name> [--framework] [--lang] [--db] [--auth] [--git] [--install] [-y] Scaffolds a new project with optional headless CLI flags.

fogoe update — Upgrades all project dependencies to their latest compatible versions.
fogoe init — Initializes Git repository, sets branch to main, and connects remote origin.
fogoe push "<msg>" Commit message Stages all files, commits with provided message, and pushes to remote repository.

AI Intelligence

AI-Assisted Scaffolding Engine

Fogoe includes a deterministic requirement compiler that translates natural language prompts into verified CLI parameters—bypassing fuzzy code generation and hallucinations with 100% template precision.

AI Prompt Command
$ fogoe create store-api \ --ai "Fastify e-commerce API with PostgreSQL, Drizzle ORM, and JWT authentication"

How Fogoe's AI Compiler Operates

Unlike generic LLM generators that attempt to write JavaScript code from scratch (frequently introducing broken imports and syntax bugs), Fogoe parses your natural language prompt against verified internal vocabulary models:

  • Framework Extraction: Detects mentions of Fastify, Express, Hono, Koa, or synonyms (e.g., "ultra-high performance" → Fastify, "edge service" → Hono).
  • Database & ORM Mapping: Maps terms like "drizzle", "prisma", "postgres", "mongo", or "sqlite" to exact driver combinations and schemas.
  • Auth & Security: Automatically activates JWT Bearer middleware when keywords like "jwt", "auth", "tokens", or "secure login" appear.
  • Architecture Selection: Chooses MVC when databases or routes are specified, or Minimal for microservices and single-endpoint servers.
Explicit Flag Overrides
You can combine --ai with explicit CLI flags. Explicit flags take priority:

fogoe create billing-svc --ai "TypeScript API with Drizzle and JWT" --framework express

Code Generation

Full CRUD Vertical Slice Generator

fogoe g crud <name> writes production-ready Models, Controllers, and REST Routes in a single atomic step. Pre-wired with standard HTTP verbs, status codes, and type safety.

bash
$ fogoe g crud product

Generated Artifacts Breakdown

Running the command creates 3 synchronized files tailored to your project's active framework and database:

src/routes/product.routes.ts
import { Router } from "express"; import * as productController from "../controllers/product.controller.js"; const router = Router(); router.get("/", productController.listProducts); router.get("/:id", productController.getProductById); router.post("/", productController.createProduct); router.put("/:id", productController.updateProduct); router.delete("/:id", productController.deleteProduct); export default router;
src/controllers/product.controller.ts
import { Request, Response } from "express"; import * as ProductModel from "../models/product.model.js"; export const listProducts = async (req: Request, res: Response) => { try { const items = await ProductModel.findAll(); res.json(items); } catch (err) { res.status(500).json({ error: "Failed to retrieve products" }); } }; export const getProductById = async (req: Request, res: Response) => { const item = await ProductModel.findById(req.params.id); if (!item) return res.status(404).json({ error: "Product not found" }); res.json(item); }; export const createProduct = async (req: Request, res: Response) => { const created = await ProductModel.create(req.body); res.status(201).json(created); };
src/models/product.model.ts
export interface Product { id: string; name: string; price: number; createdAt: Date; } export const findAll = async (): Promise<Product[]> => { // Integrated query using active ORM (Drizzle, Prisma, or native driver) return []; }; export const findById = async (id: string): Promise<Product | null> => { return null; }; export const create = async (data: Partial<Product>): Promise<Product> => { return { id: "p_1", name: data.name || "", price: data.price || 0, createdAt: new Date() }; };

Language & Module System Support #

TypeScript 5.x First

Fogoe configures TypeScript with optimal defaults targeting ES2022:

  • "module": "NodeNext" and "moduleResolution": "NodeNext" for native Node.js ES Modules.
  • Strict type-checking enabled ("strict": true).
  • Development powered by tsx watch for instant reload without build steps.
  • Clean path aliases configured for MVC architectures:
    • @routes/* → src/routes/*
    • @controllers/* → src/controllers/*
    • @models/* → src/models/*
    • @middlewares/* → src/middlewares/*
    • @config/* → src/config/*

JavaScript (ESM & CommonJS)

Full support for modern ES Modules (import / export) with "type": "module" in package.json, or classic CommonJS (require / module.exports).

Architecture Blueprints #

1. Minimal Architecture Pattern

Single entry point with health check route. Best for microservices, lambdas, and single-file prototypes:

Directory Tree
my-api/ ├── src/ │ └── server.ts ├── .env ├── .gitignore ├── package.json └── tsconfig.json

2. Layered MVC Architecture Pattern

Enterprise-ready separation of concerns with dedicated lifecycle boundaries:

Directory Tree
my-api/ ├── src/ │ ├── server.ts # Server bootstrap & port listening │ ├── app.ts # Middleware registration & route mounting │ ├── config/ │ │ ├── env.ts # Validated environment variables │ │ └── db.ts # Database pool & connection lifecycle │ ├── controllers/ │ │ └── home.controller.ts │ ├── routes/ │ │ └── home.routes.ts │ ├── models/ │ │ └── home.model.ts │ ├── middlewares/ │ │ └── authMiddleware.ts # JWT Bearer token inspection │ └── utils/ │ └── hashing.ts # Password hashing helpers ├── drizzle.config.ts # (If Drizzle ORM selected) ├── prisma/schema.prisma # (If Prisma ORM selected) ├── .env ├── .gitignore ├── package.json └── tsconfig.json

Authentication & Security #

Production JWT Bearer Middleware

When --auth jwt is enabled, Fogoe generates an authMiddleware that inspects incoming Authorization: Bearer <token> headers, verifies signatures with process.env.JWT_SECRET, attaches the decoded payload to the request context, and returns standard HTTP 401 / 403 responses on failure.

Password Hashing

Includes a pre-configured hashing utility in src/utils/hashing:

  • --hashing bcrypt: Industry standard using bcrypt.
  • --hashing argon2: Winner of the Password Hashing Competition (memory-hard).
  • --hashing crypto: Zero-dependency hashing powered by Node's native crypto.scrypt.

Git & GitHub Automation #

Fogoe automates the entire repository lifecycle:

  • Stack-Tailored .gitignore: Automatically excludes .env, node_modules/, dist/, SQLite database files (*.db, *.sqlite), and OS artifacts.
  • Automated Initial Commit (--commit): Stages all scaffolded files and writes an initial git commit.
  • Remote GitHub Setup (--github, --private): Connects to existing remote repositories or provisions new ones via GitHub CLI (gh repo create).

Troubleshooting & FAQ #

Q: Do I need to install Fogoe globally?

No. You can run Fogoe directly on demand with npx fogoe, pnpm dlx fogoe, bunx fogoe, or yarn dlx fogoe.

Q: Why does Fogoe use on-disk templates instead of embedded template strings?

Embedded string templates often suffer from syntax errors, difficult formatting, and escaping issues. Fogoe keeps pure, syntax-checked template files on disk, ensuring atomic and deterministic file generation every time.

Q: How do I run my generated project?

Navigate to your project directory and run npm run dev for hot-reloading development or npm run build && npm start for production builds.
