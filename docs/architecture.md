# Fogoe Scaffolding Architecture & Templates

Detailed layout of project architectures generated by Fogoe, along with on-disk template design and repository layout.

---

## 📁 Scaffolding Architectural Patterns

### 1. Minimal Architecture
Designed for microservices, lightweight webhooks, and single-purpose utilities.

```text
my-api/
├── .env.example
├── .gitignore
├── README.md
├── package.json
└── src/
    └── server.ts (or server.js)
```

- **JavaScript:** Uses standard Node.js native or framework instance directly in `server.js`.
- **TypeScript:** Configured with `tsconfig.json` using `NodeNext` or CommonJS module resolution.

---

### 2. MVC Architecture (Layered Vertical Slice)
Designed for production web services, domain-driven backends, and multi-entity APIs.

```text
my-api/
├── .env.example
├── .gitignore
├── README.md
├── package.json
├── drizzle.config.ts (or prisma/schema.prisma)
├── fogoe.config.json
├── tsconfig.json
└── src/
    ├── app.ts                 # Express/Fastify/Hono/Koa app initialization
    ├── server.ts              # Port listener & graceful shutdown handlers
    ├── config/
    │   ├── db.ts              # Database connection pool / ORM client
    │   └── env.ts             # Typed environment variable loader
    ├── controllers/
    │   └── homecontroller.ts  # Route handlers & business logic
    ├── middlewares/
    │   └── authMiddleware.ts  # JWT bearer authentication middleware
    ├── models/
    │   └── model.ts           # Schema & query abstractions
    ├── routes/
    │   └── home.ts            # Route definitions & parameter validation
    └── utils/
        └── hashing.ts         # Password hashing helpers (bcrypt / argon2)
```

## 🏗️ On-Disk Template Engine

Fogoe uses real `.js` and `.ts` template files located directly on disk inside `templates/`, rather than embedded string literals or regex concatenation.

### Key Benefits:
1. **Full IDE Support:** Templates are formatted, linted, and type-checked during development.
2. **Zero Syntax Bugs:** Code generation is atomic and deterministic without string escaping errors.
3. **Layered Composition (`src/composer.js`):** Projects are built by layering:
   - `templates/base/`
   - `templates/runtimes/<framework>/<language>/<module>/<architecture>/`
   - `templates/databases/<database>/<language>/<module>/`
   - `templates/auth/<auth>/<framework>/<language>/<module>/`
   - `templates/tooling/<tool>/`

## 📁 Repository Directory Structure

```text
fogoe/
├── bin/              # CLI executable entry point (#!/usr/bin/env node)
├── src/              # Core CLI engine, AI parser, composer, CRUD generators, doctor, installer
├── templates/        # Clean on-disk project templates (Fastify, Express, Hono, Koa)
├── site/             # Interactive web configurator & docs showcase source (Vite)
├── test/             # Native node:test unit & integration test suites
├── docs/             # Detailed GitHub markdown documentation
└── .github/          # GitHub Actions CI matrix and Pages deployment workflows
```
